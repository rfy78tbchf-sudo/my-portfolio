The sheet preserves the selected period's existing KRW/native-currency results and partial-coverage wording. It displays the last saved decision before the period and up to 20 decisions within it; within-period decisions are explicitly not asserted to precede a particular sale. There is no inferred sale reason or hypothetical hold-return calculation.

Owners record their retrospective sale reason, lesson and next-trade rule. Notes are persisted in Supabase per user, security and exact date range. Unsaved edits use the existing close confirmation. Revision checks reject stale writes, and save completion requires an exact server readback; a lost save response can recover from a matching readback.
