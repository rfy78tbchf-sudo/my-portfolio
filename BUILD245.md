The read-only realized-sales RPC preserves every original amount, status and count. A new optional average_cost_estimate attaches actual net sale proceeds minus sold quantity times the latest positive broker average observed before the sale date, within seven days, on the same account/security/currency. Pending executions use collected sale proceeds and explicitly mark selling costs unfinalized. Exact broker asset IDs in the account ledger resolve duplicate symbol registry entries; conflicting identities remain uncalculated. Known intervening transfers/splits block an estimate. Legacy backfills, same-day/post-sale snapshots and stale/zero averages are rejected. For foreign holdings, the collector requests std_crncy_f=2: avg_cost is a KRW unit price despite the holding currency. Convert it only with an archived daily snapshot FX whose account, security, date, currency, quantity, average, market price and value exactly match the observation. This is a reference converted basis, not the original native acquisition average. Missing/mismatched basis FX blocks the estimate. Foreign reference KRW uses an available sale-day-or-prior seven-day FX rate and stays missing when FX is unavailable.

These are reference estimates, not reconstructed moving-average allocations: later purchases can change actual cost, and multiplying foreign profit by a reference FX rate does not include acquisition-to-sale currency gains. The existing realized display opts in, labels both total and rows as estimated, and exposes average basis date/cost status in its existing disclosure. Reconciled broker amounts and complete closed-cycle results take priority. Original period P&L, dividends/cash flows, currency grouping and verified decomposition do not adopt these estimates. No financial ledger writes, new network requests, new account scope, or wealth changes.
