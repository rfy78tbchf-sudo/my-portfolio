# Build242 — manual refresh rechecks recent history

Reproduced the real Build241 refresh functions against synthetic services: a new history revision arriving one minute after successful history sync remained invisible through manual refresh because the five-minute current-month TTL skipped the collector. Five deterministic runs all issued one balance request, zero history requests. After TTL expiry the same synthetic revision appeared. This is separate from genuinely missing cost/order evidence; no claim is made that it resolves all uncalculated sales.

Manual broker refresh now requests history whose last successful request started before the user's refresh. Balance/asset display stays in the foreground; recent history remains sequential in the background. Automatic TTL and price TTL are unchanged. Concurrent manual requests wait for existing work and share sufficiently fresh requests. Failed requests do not advance the successful-start marker; waiting work is discarded when the session changes. No calculation, currency, financial record, UI layout or backend credential changes.
